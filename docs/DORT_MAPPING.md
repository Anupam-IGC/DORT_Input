# DORT Mapping Used by the API

This note explains how the Python data structures map to the DORT R-Z input arrays.

## Internal array convention

The API stores all 2-D maps as:

```python
shape == (nz, nr)
```

Therefore:

```python
map[z_index, r_index]
```

is the natural indexing convention.

## DORT dimensions

For ordinary R-Z geometry:

```text
I -> R
J -> Z
```

Hence:

```text
IM = number of R intervals
JM = number of Z intervals
```

and the writer reports:

```python
writer.required_control_values
```

with:

```text
IZM
IM
JM
INGEOM = 1
```

## 2* array

`2*` contains the Z fine-mesh boundaries.

Length:

```text
JM + 1
```

Generated by:

```python
writer.array2()
```

## 4* array

`4*` contains the R fine-mesh boundaries.

Length:

```text
IM + 1
```

Generated by:

```python
writer.array4()
```

## 8$ array

`8$` contains the material-zone number for every fine-space cell.

The API first produces:

```python
writer.zone_map
```

with shape:

```text
(JM, IM)
```

The expanded one-dimensional stream is:

```python
writer.ijzn_stream()
```

and is equivalent to:

```python
writer.zone_map.ravel(order="C")
```

Thus the order is:

```text
J=1: I=1, I=2, ... I=IM
J=2: I=1, I=2, ... I=IM
...
J=JM
```

Length:

```text
IM * JM
```

The formatted writer uses FIDO `R` compression for repeated values and `Q` compression for repeated complete radial rows.

## 9$ array

`9$` maps each DORT zone to a material number.

Generated by:

```python
writer.array9()
```

Length:

```text
IZM
```

Do not confuse this with the internal `Material.dort_id`.

If the actual GIP/cross-section material identifiers differ, supply:

```python
writer = DORTWriter(
    model,
    material_numbers={
        "Sodium": -169,
        "SS316": -145,
    },
)
```

## Zone policy

### Region policy

```python
DORTWriter(model, zone_policy="region")
```

A distinct zone is generated for each final geometric owner.

This permits:

```text
vessel -> SS316
shield -> SS316
```

to remain two zones while both map to the same material number.

### Material policy

```python
DORTWriter(model, zone_policy="material")
```

Every used material gets one zone.

Use this when minimizing `IZM` is more important than preserving region identity.

## 84$ helper

The writer can generate:

```python
writer.array84_identity()
```

which produces one edit region per generated material zone:

```text
edit region = zone number
```

This is a helper only. A real calculation may require a different edit-region grouping.

## Validation rule

Always compare:

```python
writer.summary_text()
```

against the full DORT deck before execution.

At minimum verify:

```text
IZM
IM
JM
INGEOM
2* length
4* length
8$ length
9$ length
```
