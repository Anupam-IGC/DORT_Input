Current Scope and Limitations
=============================

The project deliberately automates the parts of the local DORT workflow that
have been verified from working decks, supplied helper programs, or explicit
code behavior.  It does not invent meanings for unverified local modifications.

Implemented at a high level
---------------------------

* R-Z mesh, materials, regions, priorities, validation, and plotting;
* Excel mixture import, ``mix.inp``/name/card generation, and ``mixf.cr`` validation;
* local negative ``9$$`` cross-section references;
* DORT geometry/material arrays and selected edit-region helpers;
* legacy and product angular quadrature;
* readable first-eigenvalue, rerun, and fixed-source run controls;
* unit-20/unit-21 restart-file preparation;
* fixed-source ``INPSRM=2`` spatial + energy representation.

External mixture limits
-----------------------

The mixture API intentionally mirrors the supplied spreadsheet + ``m_ia_oa.for``
workflow. Spreadsheet import requires ``pandas`` and ``openpyxl`` and assumes
that the mixture columns appear after ``MAT No.``. The external mixer assumes:

* 217 energy groups;
* 220 cross-section columns per group;
* at most 112 distinct microscopic MAT numbers;
* at most 70 mixtures;
* at most 20 microscopic components per mixture;
* Legendre order no greater than 6.

The API writes/validates the external mixer files; it does **not** replace the
Fortran cross-section calculation itself.

Run-control limits
------------------

The readable settings layer covers the controls that are useful in normal work
and that have been mapped with confidence.  Site-specific or locally modified
controls that are not yet exposed remain available through
``set_raw_dort62(...)``.

The full local interpretation of every ``62$$`` field should continue to be
checked against a known working template or the modified DORT source.

Fixed-source limits
-------------------

The high-level source builder currently targets the verified ``INPSRM=2`` form:

.. code-block:: text

   96** = one R-Z spatial field
   98** = one common group spectrum

Full-by-group spatial fields (``INPSRM=1``) and the three-factor form
(``INPSRM=3``) are not yet generated by the high-level source API.

Complete-deck generation
------------------------

The project currently writes validated fragments rather than a universal
complete input deck.  This is intentional: trusted local template cards can be
retained while the geometry, mixtures, quadrature, run controls, and source
fields are generated programmatically.
